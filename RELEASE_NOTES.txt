# CapturePlay v0.8.11 Release Notes

Build ID: v0.8.11-20260901-beta-bootstrap-staging-retry-fix

## Improvements
- Adds an in-app **Beta update** opt-in under Settings / Update. Stable remains the default channel, and Beta can be enabled or disabled without a password or public Beta download page.
- Separates signed Stable (`delta-latest.json`) and Beta (`beta-latest.json`) feeds while retaining the existing Ed25519 schema-2 trust contract used by formal v0.8.9 clients.
- Keeps signature, SHA-256, exact size, trusted URL, exact Version / Build ID base, final-file manifest, staged health-check and rollback verification on both channels.
- Beta OFF follows the latest Stable and uses the protected Stable Full Setup when a verified forward delta chain cannot safely return the installed Beta.
- Keeps ASAR enabled while unpacking `src/**/*`, and uses 64 KiB blocks for remaining large changed files so normal JS/CSS/HTML/resource updates stay small.
- Keeps native EXE / DLL changes fail-closed for delta publication; installer provenance changes continue to use Full Setup and later Versions return to delta.

## Windows staging resilience
- Adds bounded Windows retry handling when the updater clones/removes the sibling staging tree and encounters transient `EPERM`, `EBUSY`, `EACCES` or `ENOTEMPTY` locks.
- Cleanup failure can no longer overwrite the original preparation error. If a preparation step still fails, the user sees the real phase (`staging`, package download, delta apply, final verify, health-check or swap preparation) instead of a misleading cleanup-only EPERM.
- Health-check scratch cleanup is also best-effort with bounded retries so a temporary cleanup lock cannot turn an otherwise successful health-check into a false updater failure.

## Beta-first workflow
- v0.8.11 is the Stable bootstrap for Beta-first review. After this bootstrap is installed, ordinary user-review candidates are delivered as signed in-app Beta updates: automated validation -> `BETA_READY` -> Beta feed -> user review -> Stable promotion.
- Active Beta publication keeps only the newest Beta plus the minimum signed delta chain needed to reach it. Stable and rollback evidence remain retained.

## Bootstrap installation path
- The formal v0.8.11 publication is a **new Full Setup baseline**. Formal v0.8.9 does not receive an active v0.8.9 -> v0.8.11 delta chain.
- Reason: the staging tree is created by the currently installed updater. The v0.8.9 updater can hit a transient Windows sibling-staging EPERM before the v0.8.11 retry code is available, so the bootstrap uses the explicitly allowed initial-Beta-bootstrap / updater-failure Full Setup fallback instead of pretending the target-side retry can repair the old client in advance.
- The exact v0.8.11 Setup was validated as an in-place upgrade from installed v0.8.9 with settings preserved, accepted native helper unchanged and installed health PASS.
- After v0.8.11 is installed, subsequent compatible Stable/Beta releases return to signed delta updates from v0.8.11 and benefit from the new staging retry/error-preservation behavior.

## Compatibility
- Capture, recording, screenshots, audio, diagnostics and accepted GC575/GC510 low-latency behavior are unchanged by this updater/bootstrap release.
- The multiple-monitor / different-video-source workflow was evaluated before this bootstrap and is assigned to the v0.9.0 feature line for the first normal post-bootstrap Beta candidate.
- v0.8.10 was withdrawn before formal promotion after its first public updater E2E exposed a transient staging-cleanup error-masking problem; its bytes are not reused or replaced under the same Version.
