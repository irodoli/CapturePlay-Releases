# CapturePlay v0.8.9 Release Notes

Build ID: v0.8.9-20260830-delta-bridge-resize-recording-retry-rollback-native-full-stability

## Improvements
- Adds the signed delta-update bridge used by future CapturePlay updates. Update manifests are Ed25519 verified, require exact Version / Build ID / file SHA-256 bases, and are applied to a verified staging copy before safe replacement.
- If the installed base or delta chain cannot be verified, CapturePlay keeps the current working version and offers the protected ConoHa Full Setup recovery route instead of downloading a GitHub Full fallback.
- Temporary network timeouts, HTTP 429 and server 5xx failures remain retryable and do not incorrectly force the Full Setup recovery path.
- A failed or rolled-back delta apply is reported once on the next launch; rollback restoration is treated as a required operation rather than a best-effort silent move.
- Windows Smart App Control can reject newly copied unsigned native executables. CapturePlay therefore does not publish a normal delta when `resources/native` EXE/DLL bytes change; those releases use the protected Full Setup path. v0.8.9 itself contains a native resize fix, so v0.8.8 reaches this bridge through the final legacy Full update.
- Makes the separated low-latency preview resilient to interactive window resizing by deferring transient swap-chain rebuild failures and retrying after sizing completes.
- Keeps the recording Stop control available while recording remains active even if preview activity changes transiently.
- Prevents a dismissed update error from passively reopening as a full-window blocking overlay during recording-state broadcasts.

## Compatibility
- v0.8.9 is the delta bridge. Existing v0.8.8 clients use the final legacy GitHub updater path to reach this bridge. Releases after v0.8.9 use signed sequential delta packages and do not add new GitHub Full Setup assets.
- Capture, audio, recording quality, capture diagnostics and accepted GC575 low-latency behavior are otherwise unchanged.
